## 1. Принцип (что переносимо)

**Переносимо:**
- A: reduce-only TP Limit, выставляется в момент fill входа, без последующих изменений.
- B: фиксированное расстояние в R-units, **не** в %.
- C: maker-fee на выходной ноге (0.02%), taker на входной (0.055%).
- D: SL остаётся как catastrophic (рабочий бот его не использует, мы обязаны — наши guards 1.5%/$0.92 daily).

**Не переносимо (специфика бота):**
- Grid-уровни по обеим сторонам.
- Averaging вниз против движения.
- Двусторонний market-making (это другая стратегия).
- Отсутствие SL.

## 2. Один механизм для TradingOS

```
on_position_filled(pos):
    tp_px = pos.entry + R_PCE × |pos.entry - pos.sl| × sign(pos.side)
    place_reduce_only_limit(pos.symbol, opposite(pos.side),
                            qty = pos.qty_full,
                            price = tp_px,
                            reduceOnly = True,
                            postOnly = True)            # maker fee
    SL не трогаем.
on_tp_filled | on_sl_hit | on_timeout_72h:
    log(exit_type, exit_px, NET, ΔvsREAL, ΔvsP3)
```

Никаких state machines, partial, trails, перестановок.

## 9. Ответы на 3 вопроса

**1. МОЖЕТ ЛИ ЭТО ЗАБИРАТЬ БОЛЬШЕ NET?**
Да, но только на **узкой зоне 0.9-1.0R**, только на **BUY-стороне**, и эффект **сильно зависит от 1-2 топ-сделок**.

**2. ПОЧЕМУ ЭТО ДОЛЖНО РАБОТАТЬ?**
Pre-committed TP исключает предсказание. Maker-fee экономит на выходной ноге. На коротком хвосте цена просто возвращается к SL (без прибыли но и без полга). На длинном хвосте фиксирует +0.75R / +1R.

Но: capture 1.0R = реализованная NET — мы НЕ захватываем MFE beyond 1R. Это trade-off, не gain.

**3. МИНИМАЛЬНЫЙ МЕХАНИЗМ ДЛЯ ПРОВЕРКИ LIVE?**
**Гибрид B (25% @ 0.5R + 75% @ 1.0R)** как read-only paired shadow profile:
- partial TP1 at +0.5R (25% qty, postOnly reduce-only limit, maker fee)
- partial TP2 at +1.0R (75% qty, postOnly reduce-only limit, maker fee)
- SL остаётся catastrophic (2R по умолчанию)
- timeout 72h

Нет дополнительных state machines, нет перестановок.
