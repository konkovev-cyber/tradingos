# TradingOS Component Ownership

## Текущая архитектура (проблемная)

```
Telegram Control (команды человека)
       |
TradingOS Kernel (мониторинг)
       |
PIE Observer (смотрит)
Position Guard (принимает решения)
       |
ubot_bingx (стратегия + исполнитель + SL/TP менеджер) ❌ конфликт
       |
BingX
```

**Проблема:** ubot_bingx выполнял 3 роли одновременно — стратегия, исполнитель, SL/TP менеджер. Guardian не мог контролировать позиции, потому что ubot_bingx отменял ордера.

## Целевая архитектура

```
Человек → Trading Control (только команды)
               |
         TradingOS Kernel (мозг)
               |
         ┌─────┴─────┐
         v           v
      Observer    Guardian (только решения)
      👀           🛡️
                     |
               Executor (один!)
                     |
                  BingX
```

## Роли

| Компонент | Может смотреть | Может менять ордера | Статус |
|-----------|---------------|-------------------|--------|
| Trading Control Panel | нет | только команды человека | ✅ |
| TradingOS Kernel | да | нет | ✅ |
| PIE Observer | да | нет | ✅ |
| Position Guard | да | только после approval | 🟡 DRY_RUN |
| ubot_bingx | ❌ отключён | ❌ отключён | ❌ STOPPED |
| Executor (v1) | да | да | ❌ НЕ ОПРЕДЕЛЁН |

## Решение

**Сейчас** — ubot_bingx выключен. Позиции живут на бирже с SL/TP. Guardian работает в DRY_RUN.

**Следующий шаг** — определить одного исполнителя. Варианты:
- A) Очистить ubot_bingx от защиты, оставить только исполнение
- B) Создать TradingOS Executor
- C) Оставить без исполнения (ручное открытие)

**Правило:** Один исполнитель. Один владелец ордеров.
