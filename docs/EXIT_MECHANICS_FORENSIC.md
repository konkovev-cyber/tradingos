# Exit-Mechanics Forensic (2026-08-16) — FROM MICRO-EDGE TO NET PnL

**Вопрос:** может ли замена «ENTRY → фиксированный SL → фиксированный TP» на механику управления позицией (ladder / partial TP + runner / time-exit) увеличить реальный NET PnL при сохранении текущего качества входов?

**Метод:** read-only историческая симуляция на РЕАЛЬНЫХ путях. 34 закрытых AUTO-сделки (08-07..08-14) из `trade_lifecycle.jsonl`; для каждой — M15 OHLC path от entry до entry+72h, скачанный через публичный Bybit klines API (не look-ahead: только бары после момента входа). Фичи сделки (entry/SL/TP/side/фичи сигнала) и costs (size/fees/net) — из реальных журналов. Экономика едина для всех механик: **risk = $0.50/сделку** (конфиг), qty = risk/|entry−SL|, fee taker 0.055%×2, slippage 2bps на выход. Интрабар: консервативный (при касании SL и TP в одном баре — SL первый; для ladder — проверка SL против текущего уровня до подтяжки).

Скрипты: `/tmp/exit_sim/{build_dataset,control_a_e,simulator,simulator2,robustness,robustness2,control_b_cases}.py`, датасет `/tmp/exit_sim/dataset.pkl`.

## ФИНАЛЬНЫЙ ВЕРДИКТ

### 🏆 WINNER — P3: Partial TP @+1.0R + trailing runner (33/67)

**Механика (LONG; SHORT зеркально):**
1. Вход с исходными SL (−1R) и TP как сейчас (катастрофическая защита НЕ убирается).
2. При достижении **+1.0R** → закрыть **33%** позиции по market/limit.
3. Остаток (67%) — runner: трейлинг-стоп **0.75R позади максимального favourable экстремума** (от дневного/интрабар high для LONG), TP оставить как предельный ориентир (runner может доехать до него или быть выведен трейлом).
4. Если runner не тронул +1.0R — позиция живёт с исходным SL/TP, никаких ранних подтяжек.

**Почему работает:** фиксирует ⅓ прибыли до отката (цена касается +1.0R до SL в 18/34 сделок), но не душит хвост — runner удерживает движение, которое рынок реально даёт (MFE 2.17R медиана). Ранние подтяжки (≤0.5R) доказанно вредны (C1 −$2.53, C2 −$3.20) — их нет.

**Экономика (34 сделки, risk $0.5):** NET **+$1.82** (taker) / **+$2.50** (maker) vs факт +$0.155. WR 56–60%, медиана +$0.25. Устойчив к SL-pct фильтру, TRAIN/OOS, удалению символов.

**Риски / честные оговорки:**
- n=34, окно 8 дней — этого МАЛО для твёрдого доказательства; требуется shadow/live подтверждение (ниже).
- Симуляция на M15 путях: интрабар консервативен, но реальные лимитные/трейл-ордера имеют спред и риск неполного исполнения (частично покрыт slippage 2bps).
- OOS всего 11 сделок — плюс сохраняется, но статистически слаб.
- Guardian-стек (BE/PARTIAL/TIGHT) НЕ должен применяться поверх P3 одновременно — это две конкурирующие механики выхода; при live включается одна.

**Что менять в коде:** `guardian/reality_guardian.py` — параметризуемый exit-профиль: `partial_frac=0.33, partial_at_R=1.0, trail_R=0.75`, runner-ветка вместо текущего BE@0.8/PARTIAL@1.0/TIGHT@1.5. `strategies/trade_executor.py` — вход PostOnly (maker), fallback taker. Обязательные тесты перед live: 34-сделочный replay = результат симуляции (контрольная сумма), интрабар SL-first для LONG/SHORT, trail не ниже исходного SL, порядок partial→runner→trail, maker fallback при неисполнении.

**Движок:** `research/exit_shadow/exit_shadow_engine.py`, systemd `tradingos-exit-shadow.service` (active, enabled). Restart-safe: симуляция детерминированно пересчитывается с entry по закрытым M15-барам (публичный Bybit API).

**Профили в ledger (на каждую новую AUTO-сделку):**
- `real` — фактическая сделка production (включая guardian-ladder/ручные закрытия).
- `A_p3_taker` — P3-выход с реального входа: 33% @ +1R, runner trail 0.75R, исходные SL/TP; экономика по фактическому size: taker 0.055%/ногу + slippage 2bps + funding est.
- `B_maker_cur` — фактический выход + maker-вход fee-оценка (fill не гарантирован).
- `C_maker_p3` — P3-путь + maker-вход fee-оценка.
- `delta_A/delta_B/delta_C` — per-trade разницы vs факта (главная метрика систематичности).

**Консервативная семантика симуляции** (`sim_mode` в каждой записи): SL-first при двойном касании (бар коснулся и SL, и +1R → полный SL без partial); partial @+1R перед TP (path-зависимость); trail обновляется в конце бара → действует со следующего (lag 1 бар); таймаут 72ч → выход по последнему close; только ЗАКРЫТЫЕ бары. Закреплено тестами `test_exit_shadow_sim.py` (11/11 PASS).

**Предзапусковая валидация на 34 исторических сделках (live-симулятор, ужесточённый):** NET **+$1.205** (forensic-оценка +$1.82 без trail-lag; факт +$0.155), медиана +$0.105, WR 56%, **Δ(A−REAL) положительна в 23/34 сделок** (медиана +$0.017, mean +$0.031) — улучшение систематическое, не хвостовое. Сквозной smoke-тест конвейера финализации на реальной сделке (MMTUSDT 08-14) — PASS.

**Gate в production (фиксирован пользователем 16.08, отчёт: `research/exit_shadow/exit_shadow_report.py`):**
1. ≥ 30 финализированных shadow-сделок;
2. A (P3) NET > 0;
3. A NET > REAL (CURRENT) NET;
4. expectancy A > 0;
5. PF A > 1;
6. результат не объясняется 1–2 сделками (top-2 < 100% NET);

9. реальные издержки учтены (taker fees + slip + funding — по построению ledger);
