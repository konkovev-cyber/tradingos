This file tracks which version of the CIO Operating Directive is current.

```text

    CIO_OPERATING_DIRECTIVE_v1.md

Superseded by:
    (none)

Created:
    2026-07-30

Approval status:
    APPROVED

Related documents:
    (none yet)

Future plans:
    CIO_PLAYBOOK.md — daily procedures, report templates,
                      checklists. Updated more often than policy.
```

## Versioning rule

- Do not edit `CIO_OPERATING_DIRECTIVE_v1.md` after approval.
- If policy changes, create `CIO_OPERATING_DIRECTIVE_v1.1.md` or `CIO_OPERATING_DIRECTIVE_v2.0.md`.
- Update this registry on every version change.
- The body of the directive stays immutable. The registry reflects the active version.

## Policy vs Procedure split

```
CIO_OPERATING_DIRECTIVE_v1.md   — management principles (immutable)
                                 — 7-question daily format
                                 — forbidden/allowed list
                                 — decision rules (CONTINUE/FIX/SCALE/TUNE/STOP)
                                 — DECISION READINESS axes

CIO_PLAYBOOK.md (planned)        — operational procedures (evolves)
                                 — exact report templates
                                 — calculation formulas
                                 — recommendation workflow
                                 — directive compliance check
                                 — diagnostic question trees
                                 — limitation classification probabilities
```

## Why this split

The directive is the project's management constitution. It changes only when the project itself changes its operating philosophy.

The playbook is the operational handbook. It can be refined after each closed trade, each metric appears, each observed operational event.

Stability of policy prevents re-litigation. Flexibility of procedure allows adaptation to data.
