# Accounting / Guard Forensic (2026-08-14/15)

**Вопрос:** где считается дневной NET и почему 08-09 убыток **−$1.79** прошёл через дневной лимит **$1.19**?

---

## 1. Где считается дневной NET

| Место | Что делает | Статус |
|---|---|---|
| `deposit_guard.can_open_position()` (#4 hard kill, #5 daily limit) | `daily_pnl = equity − day_start_equity` (equity-базис, включает unrealized + fees) | Проверяется **только в момент попытки AUTO-входа** |
| `deposit_guard.on_trade_closed(realized_pnl, fees)` | накапливает `realized_pnl_day`, `fees_day` (аудит) | **fees не передавались** (вызов без аргумента fees) — исправлено |
| `deposit_guard.on_equity_sample(equity)` | периодическая выборка equity (guard срабатывал бы mid-day) | **МЁРТВЫЙ КОД** — никем не вызывается |
| Ручной контур (`manual_signal.py`) | `max_session_loss_usd: $3.0` | **Только отображается** в /session (строка 288), не применяется; guard не вызывается вообще |

## 3. Три структурные причины

1. **Ручной контур полностью вне guard**: `manual_signal.py` не вызывает `can_open_position`; `max_session_loss_usd` только показывается. → лимит $1.19 на ручные входы не действовал.
2. **Guard оценивает equity только в момент AUTO-входа**: между проверками (часами) убытки накапливаются; `on_equity_sample` никто не вызывает.
3. **Guard не закрывает позиции** (по дизайну): реализованные убытки открытых позиций проходят всегда — блокируются только НОВЫЕ входы.

## 4. Что исправлено (2026-08-15)

1. `reality_guardian.py:1504`: `on_trade_closed(net_pnl, fees=fees)` — `fees_day` теперь реальный.
2. `deposit_guard.py`: `_sync_from_disk()` + fcntl-lock в `_save_state()` — устранён **cross-process clobbering state** (guardian- и reality-процессы затирали поля друг друга: `losing_streak`, `blocked_new_entries`, `fees_day`). Тест PASS: два «процесса» накапливают realized/fees без потери (−0.50+0.03 → +0.20+0.02 = −0.30/$0.05).
3. `on_funding_paid(amount)` hook добавлен (цепочка gross→fees→funding→slippage→NET; пока неоткуда вызывать — нет позиционного funding PnL).

## 5. Осталось (структурные, требуют решения)

- **A. Подключить ручной контур к guard** (`can_open_position` перед ручным входом, иначе ручные входы блокируются при дневном убытке ≥ $1.19). Прямой ответ на «лимит запаздывает».
- **B. Периодический вызов `on_equity_sample`** (например, в цикле run_observation) — guard срабатывает mid-day, а не только при входе.
- **C. Показывать `fees_day`/`realized_pnl_day` в `/session`** — прозрачность учёта.
